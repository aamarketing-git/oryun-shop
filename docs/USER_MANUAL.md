# 오륜쇼핑몰 · 사용 설명서

본 문서는 세 역할(관리자 · 공급자 · 소비자) 각각의 사용 흐름을 안내합니다.

---

## 1. 관리자 (Admin)

### 1-1. 로그인

1. `/auth/login`에서 관리자 이메일로 로그인합니다.
2. 최초 설정 시 Supabase 대시보드에서 직접 `profiles.role='admin'`으로 갱신해야 합니다:
   ```sql
   UPDATE profiles SET role='admin' WHERE email='admin@oryun.shop';
   ```
3. 로그인 후 우측 상단 아이콘 → 자동으로 `/admin/dashboard`로 이동합니다.

### 1-2. 대시보드

`/admin/dashboard`

- 7일 매출, USDT 거래 건수, 승인 대기 공급자/상품 수
- 최근 주문 5건
- 좌측 사이드바: 대시보드 · 회원 · 공급자 승인 · 상품 · 주문 · 환율 · TXID · 배송 · 문의 · 통계

### 1-3. 공급자 승인

`/admin/sellers?status=pending`

1. 대기 중 공급자 목록 표시 (상호명·이름·연락처·계좌·USDT 주소·사업자등록증)
2. **승인** 클릭 → `approve_seller` RPC 실행 → 해당 사용자의 `profiles.role`이 자동으로 `seller`로 변경됨
3. **거절** 클릭 → 사유 입력 → `status=rejected`

> 차단: 승인된 공급자도 추후 `status=blocked`로 차단 가능 (UI 추가 필요 시 같은 컴포넌트 재사용)

### 1-4. 상품 승인 & 상세페이지 작성 ⭐ 핵심

`/admin/products?status=pending`

1. 공급자가 등록한 상품 목록 표시
2. 각 행의 **상세** 링크 → `/admin/products/{id}/detail`로 이동
3. 우측 패널에서 섹션 추가: `Hero / Feature / Spec / Gallery / Callout`
4. 각 섹션 편집 → **상세페이지 저장**
5. 목록으로 돌아와 **승인** 클릭

> 💡 상세페이지 없이 승인하면 `DETAIL_PAGE_REQUIRED` 에러가 발생합니다. 통일된 디자인을 강제하기 위한 의도된 동작입니다.

### 1-5. 환율 관리

`/admin/settings/rate`

- 현재 KRW/USDT 환율 표시 (기본 1500)
- **환율 변경** → 새 환율 입력 → 확인 다이얼로그 → 저장
- 변경된 환율은 **이후 생성되는 주문**에만 적용됩니다 (기존 주문은 스냅샷 보존)

### 1-6. TXID 조회

`/admin/txids`

- 모든 제출된 TXID 목록 (체인, 주문번호, 상태, 제출일시)
- 동일 TXID는 DB에서 자동 차단되므로 조회만 가능

### 1-7. 통계

`/admin/stats`

- 최근 30일 총 매출, 결제완료 주문 수, USDT/계좌이체 비율
- 일별 매출 라인차트, 공급자별 매출 Top 10

## 2. 공급자 (Seller)

### 2-1. 회원가입

1. `/auth/register?role=seller`에서 회원가입
2. 입력 항목:
   - 이메일·비밀번호
   - 상호명·대표자명·연락처
   - 계좌정보 (은행/계좌번호/예금주)
   - USDT 지갑 주소 (TRC20/ERC20)
   - 사업자등록증 (선택, Supabase Storage 업로드)
3. 가입 직후 상태: `Pending`
4. 관리자 승인 후 판매 가능

### 2-2. 승인 대기

- 미승인 상태에서 `/seller/*`에 접근 시 **승인 대기 중** 화면 표시
- 거절/차단 시: **접근 제한** 화면

### 2-3. 대시보드

`/seller/dashboard`

- 7일 매출, 등록 상품 수, 결제 대기 주문 수
- 최근 주문 5건

### 2-4. 상품 등록

`/seller/products` → **상품 등록** → `/seller/products/new`

입력 항목:
- 상품명·간단 설명
- 가격(KRW)·재고
- 카테고리·대표 이미지 URL
- 문의 번호 (선택)
- 직접 전달 사용 여부

> 등록 직후 상태는 `pending`이며, 관리자가 상세페이지를 작성하고 승인해야 노출됩니다.

### 2-5. 주문 처리

`/seller/orders`

1. 상태별 필터링 (전체/결제 대기/완료/배송 준비/배송 중/배송 완료)
2. 행 클릭 → 주문 상세 (`/seller/orders/{id}`)

#### 결제 확인
- **계좌이체**: 실제 입금 확인 후 **결제 확인 (Paid 처리)** 클릭
- **USDT**: 소비자가 제출한 TXID 확인 → 블록체인 익스플로러로 검증 → **결제 확인** 클릭

#### 배송 등록
- **택배**: 택배사 + 송장번호 입력
- **직접 전달**: 메모 입력 (예: "강남역 1번 출구 18시")

### 2-6. 문의 조회

`/seller/inquiries`

- 상품별 문의 메타데이터 (실제 대화는 카카오톡/전화/텔레그램에서)

### 2-7. 정산 정보

`/seller/settings` (조회 전용, 수정은 관리자 요청)

## 3. 소비자 (Customer)

### 3-1. 회원가입 & 로그인

`/auth/register` (역할: customer 기본값)

이메일 · 비밀번호 · 이름 · 전화 · 오륜 스테이킹 Wallet 주소 (선택, 주문 시 자동 채움)

### 3-2. 쇼핑

`/products`

- 카테고리 필터, 검색, 정렬(최신/낮은 가격/높은 가격)
- 카드 그리드 (토스 스타일)

상품 카드 클릭 → `/products/{id}`

상세 페이지:
- 관리자가 제작한 통일된 디자인의 섹션
- 가격 + **구매하기** 버튼 + **공급자 문의** (카카오/전화/텔레그램)

### 3-3. 주문 ⭐ Staking Wallet 필수

`/checkout?product_id=...` (구매하기 버튼에서 이동)

1. 주문 상품·금액 요약
2. **오륜 스테이킹 Wallet 주소** (필수, 미입력 시 주문 불가)
3. 배송지 입력 (이름·전화·주소)
4. 결제수단 선택:
   - **계좌이체**: 공급자 계좌 표시
   - **USDT**: 현재 환율로 환산 금액 표시
5. **주문하기** → 주문 생성

### 3-4. 결제

`/account/orders/{id}` (주문 완료 후 자동 이동)

#### 계좌이체
- 공급자의 은행/계좌/예금주 표시
- 계좌번호 · 금액 **복사 버튼**
- 입금 후 공급자가 확인

#### USDT
- QR코드 (TRC20/ERC20 선택)
- 송금 주소 + **복사 버튼**
- 송금 완료 후 **TXID 제출** 폼에 트랜잭션 해시 입력
- ⚠️ 동일 TXID는 재사용 불가

### 3-5. 주문 조회

`/account/orders`

전체 주문 목록 · 상태 · 결제수단

### 3-6. 배송 조회

주문 상세 페이지 하단:
- 택배: 택배사 + 송장번호
- 직접 전달: 메모

### 3-7. 공급자 문의

상품 상세에서 카카오톡/전화/텔레그램 링크 클릭 → 외부 채널로 즉시 연결

## 화면 흐름도

```
[소비자]
홈 → 상품 목록 → 상품 상세 → (Staking Wallet 입력) 체크아웃
  → 주문 상세 → 계좌이체 or USDT(TXID 제출) → 배송 추적

[공급자]
회원가입(seller) → 승인 대기 → 승인됨 → 상품 등록(pending)
  → (관리자 상세페이지 작성 + 승인) → 판매중
  → 주문 수신 → 결제 확인 → 배송 등록 → 배송 완료

[관리자]
공급자 승인 → 상품 상세 작성 → 상품 승인
환율 관리 / TXID 조회 / 통계 모니터링
```

## 자주 묻는 질문

**Q1. 오륜 스테이킹 Wallet 주소를 모르겠어요.**
운영팀에서 별도 안내드린 스테이킹 지갑 주소를 입력하세요. 미입력 시 주문이 생성되지 않습니다.

**Q2. TXID를 잘못 입력했어요.**
공급자에게 문의해 주세요. 한 번 등록된 TXID는 사용자가 직접 수정할 수 없습니다.

**Q3. 상품을 등록했는데 노출되지 않아요. (공급자)**
관리자가 상세페이지를 작성하고 승인해야 노출됩니다. 통일된 디자인을 위해 공급자는 상세페이지를 직접 만들 수 없습니다.

**Q4. 환율이 변경되었어요.**
주문 시점의 환율이 그대로 보존됩니다 (`orders.usdt_rate`에 스냅샷). 결제 금액은 변하지 않습니다.
